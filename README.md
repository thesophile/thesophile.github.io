## Personal Portfolio

## How it works

It is a Simple & Minimal Static Portfolio Site using just HTML, Javascript and tailwindcss.
There are two projects section- The highlighted projects are pulled from projects.json
The second project section is pulled directly from github, filtered by the keyword 'portfolio'.
To add a project, go to github and add a topic 'portfolio'.
Professional projects are pulled from professional-projects.json. To add or edit them, edit that file.

### Local Installation

1. Clone it 
    ```
    git clone https://github.com/thesophile/thesophile.github.io.git
    ```

2. add submodule
    ```
    git submodule add https://github.com/thesophile/website-common.git common
    ```

2. serve it
    ```
    python3 -m http.server
    ```

    Then go to `http://localhost:8000/`

# Deployment

This site is deployed with **GitHub Pages in "Deploy from a branch" mode**. There is no
deploy script, no CI config and no `gh-pages` branch in this repo — the deployment is
configured in the repository settings (Settings -> Pages -> Build and deployment ->
Source: *Deploy from a branch*).

## Configuration

| Setting | Value |
| --- | --- |
| Source branch | `latest/eyes` |
| Source path | `/` (root of the branch) |
| Custom domain | `abhinavbabu.in` (read from the `CNAME` file) |
| HTTPS | enforced, certificate auto-renewed by GitHub |
| 404 page | `404.html` from the branch root |

## What happens on `git push`

1. A push to `latest/eyes` triggers GitHub's built-in `pages-build-deployment` workflow.
   This workflow is generated by GitHub and lives outside the repo
   (`dynamic/pages/pages-build-deployment`), which is why there is no workflow file to
   commit.
2. The `build` job checks out `latest/eyes` **including git submodules**, then builds the
   site with the `jekyll-build-pages` container and uploads the artifact.
3. The `deploy` job publishes the artifact to the `github-pages` environment, which
   serves `https://abhinavbabu.in`.
4. Any other branch (`main` included) is not published.

Check the status of a deployment:

```bash
gh run list --repo thesophile/thesophile.github.io
gh run watch <run-id> --repo thesophile/thesophile.github.io
```

## Gotcha: the `common` submodule

`common/` is a git submodule pointing at https://github.com/thesophile/website-common.git
(shared navbar CSS/JS/HTML). The Pages build checks out submodules, so the commit that
this repo pins **must exist in the `website-common` remote** — otherwise the build fails
with `fatal: remote error: upload-pack: not our ref <sha>` and nothing gets published.

So whenever you change `common/`, push the submodule **first**:

```bash
cd common
git push origin main      # publish the commit the parent repo is about to pin
cd ..
git add common            # update the pinned commit
git commit -m "update common submodule"
git push origin latest/eyes
```

If you push the parent repo first, the pinned commit will be unavailable on the remote
and the deployment will fail until the submodule commit is published.
